# 🎅 Secret Santa

A tiny static website for a Secret Santa draw. Each participant logs in with their name and a personal password and sees who they are buying a present for. Nobody else, not even the organiser running the setup, is shown the pairings.

There is no server code and no admin page. The draw happens on the organiser's computer; the website only holds encrypted results.

## Requirements

- [Node.js](https://nodejs.org/) 22.12 or newer (for the setup script and tests)
- Any static web host (GitHub Pages, Netlify, a plain web server, ...)

No packages to install.

## Files

| File | What it is |
|------|------------|
| `src/index.html` | The website: login form and result screen |
| `src/santa.js` | Drawing, password and encryption code, used by both the website and the setup script |
| `setup.js` | Script the organiser runs locally to make the draw |
| `data/assignments.json` | Encrypted draw results, generated by `setup.js`, published with the site |
| `test/santa.test.js` | Tests |
| `Dockerfile`, `nginx.conf` | Docker image that serves the site |
| `CRITERIA.md` | The requirements this project is built against |

## For the organiser

### 1. Make the draw

Run the setup script and enter the participants, comma-separated:

```sh
node setup.js
Participants (comma-separated): Anna, Erik, Ola, Kari
```

Output:

```
Wrote data/assignments.json. Send each person their password:
Anna (username: anna): e6xyjp2hrhn7
Erik (username: erik): etkg528tean7
Kari (username: kari): zgy682tgca2z
Ola (username: ola): ur69eep3swcr
```

- You need at least 2 participants, and names must be unique (case does not matter: `anna` and `Anna` count as the same).
- Usernames are lower-case, with spaces replaced by `_`: `Mary Ann` becomes `mary_ann`.
- Nobody is ever assigned to themselves.
- The script prints only names and passwords, in alphabetical order, never who got whom.
- `data/assignments.json` is always written next to `setup.js`, wherever you run it from.
- Every run makes a **new** draw with **new** passwords and overwrites `data/assignments.json`. If you rerun it, send everyone their new password.

### 2. Send out the passwords

Send each person **only their own** line, privately (text message, DM, ...). Don't post the full list anywhere, and don't keep it once everyone has their password.

### 3. Publish the website

Upload these files to your web host, keeping this layout:

| From this repo | To the site |
|----------------|-------------|
| `src/index.html` | `index.html` |
| `src/santa.js` | `santa.js` |
| `data/assignments.json` | `data/assignments.json` |

`setup.js`, the tests and the other files are not needed on the site (publishing them does no harm; they contain no secrets).

**Docker:** the image holds only the site. Mount the `data/` folder made by `setup.js` into it, read-only:

```sh
docker build -t santa .
docker run -p 8080:80 -v "$PWD/data:/usr/share/nginx/html/data:ro" santa
```

`data/` is in `.gitignore`, so the draw is never committed or baked into the image. A new draw is live as soon as `setup.js` finishes, with no rebuild or restart needed.

### Try it locally first

Browsers won't load the data file if you just double-click `src/index.html`, and the site and its data live in different folders here, so run it with Docker:

```sh
docker build -t santa .
docker run --rm -p 8080:80 -v "$PWD/data:/usr/share/nginx/html/data:ro" santa
```

Then open http://localhost:8080.

## For participants

1. Open the website link you got from the organiser.
2. Type your name exactly as in the message you got (the username) and the password you were sent.
3. Press **🎅 Ho ho ho, show me!**. It can take a second.
4. Keep it secret, and press **Log out** or close the tab when you're done.

If you see *"Rudolph doesn't recognise that name or password"*, check the spelling of your name and the password. The password has no capital letters and no `0`, `o`, `1`, `l` or `i`, so letters can't be mixed up with numbers.

## How it works

1. `setup.js` shuffles the names and has each person give to the next person in the shuffled circle, so nobody can get themselves.
2. Each person gets a random 12-character password.
3. Every name is padded to 64 bytes before encryption, so the file doesn't reveal how long anyone's assigned name is.
4. Each person's assignee is encrypted with their own password (PBKDF2-SHA256, 600,000 iterations, then AES-256-GCM) and stored in `data/assignments.json` under their name.
5. The website decrypts the entry in the browser. A wrong password fails to decrypt, so only the right password reveals the name.

## Tests

```sh
node --test
```

These check that nobody is assigned to themselves, that everyone receives exactly one present, and that a wrong password can't decrypt a result.

## Known limitations

- **The organiser could peek.** The organiser hands out the passwords, so they could log in as someone. The setup never *shows* the pairings, but it relies on the organiser not snooping.
- **The participant list is public.** Anyone who opens `data/assignments.json` can see who is taking part (but not who got whom).
- **No limit on login attempts.** A static site can't block repeated guessing. The 12-character random passwords make guessing impractical.
- **The draw is always one big circle.** You never get small loops like Anna ↔ Erik.
- **No exclusions.** You can't say "partners must not get each other". Rerun the draw if you want a different result (and resend passwords).
