# 🎅 Secret Santa

A tiny static website for a Secret Santa draw. Each participant logs in with their first name and a personal password and sees who they are buying a present for. Nobody else, not even the organiser running the draw, can find out the pairings.

There is no server code and no admin page. The draw happens on the organiser's computer; the website only holds encrypted results.

## Requirements

- [Node.js](https://nodejs.org/) 22.12 or newer (for the setup script and tests)
- Any static web host (GitHub Pages, Netlify, a plain web server, ...)

No packages to install.

## Files

| File | What it is |
|------|------------|
| `index.html` | The website: join form, login form and result screen |
| `santa.js` | Join, draw, login and encryption code, used by both the website and the setup script |
| `setup.js` | Script the organiser runs locally to make the draw from the join codes |
| `assignments.json` | Encrypted draw results, generated by `setup.js`, published with the site |
| `santa.test.js` | Tests |
| `CRITERIA.md` | The requirements this project is built against |

## How a draw goes

1. **Participants join.** Each person opens the website and uses *Join the draw*. Their browser makes a password that only they see, plus a join code. They send the join code to the organiser.
2. **The organiser makes the draw** from the join codes and publishes `assignments.json`.
3. **Participants log in** with their name and password and see who they got.

Because each password is made in the participant's own browser and never leaves it, the organiser can't log in as anyone. No one, organiser included, can find out who got whom.

## For the organiser

### 1. Publish the website and collect join codes

Upload `index.html` and `santa.js` to your web host (see [Publishing](#publishing)) and send everyone the link. Ask each person to press **🦌 Count me in!** and send you the join code it shows.

Paste the codes into a text file, one per line, e.g. `joins.txt`. Keep `joins.txt` out of the repo; it isn't secret, but there's no reason to publish it.

If someone joins twice, use only their latest code.

### 2. Make the draw

```sh
node setup.js joins.txt
```

Output:

```
Wrote assignments.json for 4 people: Anna, Erik, Kari, Ola
```

- You need at least 2 participants, and names must be unique (case does not matter: `anna` and `Anna` count as the same).
- Nobody is ever assigned to themselves.
- The script never prints who got whom, and you have no passwords, so you can't find out either.
- Every run makes a **new** draw and overwrites `assignments.json`. Participants keep their passwords; just tell them to log in again.
- A broken or mistyped code stops the script with *"Join code N is not valid"* (N is the line number, blank lines skipped).

### 3. Publish the draw

Upload `assignments.json` next to `index.html`. Then tell everyone to log in.

### Publishing

The site needs these files:

- `index.html`
- `santa.js`
- `assignments.json` (after the draw)

`setup.js`, the tests and the other files are not needed on the site (publishing them does no harm; they contain no secrets).

**GitHub Pages example:** commit the files, push, then turn on Pages under *Settings → Pages* for the `main` branch.

### Try it locally first

Browsers won't load the scripts if you just double-click `index.html`, so use a local web server:

```sh
python -m http.server
```

Then open http://localhost:8000.

## For participants

**Joining (before the draw):**

1. Open the website link you got from the organiser.
2. Under *New here? Join the draw!*, type your first name and press **🦌 Count me in!**.
3. **Write down the password** it shows. Only you will ever see it, and it can't be recovered.
4. Press **📋 Copy join code** and send the code to the organiser.

**Finding out who you got (after the draw):**

1. Open the website and type your first name and your password.
2. Press **🎅 Ho ho ho, show me!**. It can take a second.
3. Keep it secret, and press **Log out** or close the tab when you're done.

If you see *"Rudolph doesn't recognise that name or password"*, check the spelling of your name and the password. The password has no capital letters and no `0`, `o`, `1`, `l` or `i`, so letters can't be mixed up with numbers.

Lost your password? Join again, send the organiser the new code, and ask them to redo the draw.

## How it works

1. **Join:** the browser makes a random 12-character password and an RSA key pair: a public key that can only lock things, and a private key that unlocks them. The private key is encrypted with the password (PBKDF2-SHA256, 600,000 iterations, then AES-256-GCM). The join code is the name, the public key and the encrypted private key.
2. **Draw:** `setup.js` shuffles everyone and has each person give to the next person in the shuffled circle, so nobody can get themselves. Each giver's receiver name is locked with the giver's public key (RSA-OAEP) and stored in `assignments.json` under the giver's name, in alphabetical order.
3. **Login:** the website unlocks the private key with the password, then unlocks the receiver name. A wrong password fails at the first step.

Every locked receiver name is exactly the same size, so the published file gives no hints about who got whom.

## Tests

```sh
node --test
```

These check that nobody is assigned to themselves, that everyone receives exactly one present, the full join → draw → login flow, that a wrong password can't reveal a result, and that the published file doesn't leak the pairings (same-size results, alphabetical order).

## Known limitations

- **The organiser must run the real `setup.js`.** An organiser who edits the script to print the pairings, or swaps in their own join code for someone, could cheat. This protects against peeking, not against sabotage.
- **The participant list is public.** Anyone who opens `assignments.json` can see who is taking part (but not who got whom).
- **No limit on login attempts.** A static site can't block repeated guessing. The 12-character random passwords make guessing impractical.
- **The draw is always one big circle.** You never get small loops like Anna ↔ Erik.
- **No exclusions.** You can't say "partners must not get each other". Rerun the draw if you want a different result.
