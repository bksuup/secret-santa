# 🎅 Secret Santa

A tiny static website for a Secret Santa draw. Each participant logs in with their first name and a personal password and sees who they are buying a present for. Nobody else, not even the organiser running the setup, is shown the pairings.

There is no server code and no admin page. The draw happens on the organiser's computer; the website only holds encrypted results.

## Requirements

- [Node.js](https://nodejs.org/) 22.12 or newer (for the setup script and tests)
- Any static web host (GitHub Pages, Netlify, a plain web server, ...)

No packages to install.

## Files

| File | What it is |
|------|------------|
| `index.html` | The website: login form and result screen |
| `santa.js` | Drawing, password and encryption code, used by both the website and the setup script |
| `setup.js` | Script the organiser runs locally to make the draw |
| `assignments.json` | Encrypted draw results, generated by `setup.js`, published with the site |
| `santa.test.js` | Tests |
| `CRITERIA.md` | The requirements this project is built against |

## For the organiser

### 1. Make the draw

Run the setup script with every participant's first name:

```sh
node setup.js Anna Erik Ola Kari
```

Output:

```
Wrote assignments.json. Send each person their password:
Anna: e6xyjp2hrhn7
Erik: etkg528tean7
Kari: zgy682tgca2z
Ola: ur69eep3swcr
```

- You need at least 2 participants, and names must be unique (case does not matter: `anna` and `Anna` count as the same).
- Names with spaces need quotes: `node setup.js "Mary Ann" Erik`.
- Nobody is ever assigned to themselves.
- The script prints only names and passwords, in alphabetical order, never who got whom.
- Every run makes a **new** draw with **new** passwords and overwrites `assignments.json`. If you rerun it, send everyone their new password.

### 2. Send out the passwords

Send each person **only their own** line, privately (text message, DM, ...). Don't post the full list anywhere, and don't keep it once everyone has their password.

### 3. Publish the website

Upload these files to your web host:

- `index.html`
- `santa.js`
- `assignments.json`

`setup.js`, the tests and the other files are not needed on the site (publishing them does no harm; they contain no secrets).

**GitHub Pages example:** commit `assignments.json`, push, then turn on Pages under *Settings → Pages* for the `main` branch.

### Try it locally first

Browsers won't load the data file if you just double-click `index.html`, so use a local web server:

```sh
python -m http.server
```

Then open http://localhost:8000.

## For participants

1. Open the website link you got from the organiser.
2. Type your first name and the password you were sent.
3. Press **🎅 Ho ho ho, show me!**. It can take a second.
4. Keep it secret, and press **Log out** or close the tab when you're done.

If you see *"Rudolph doesn't recognise that name or password"*, check the spelling of your name and the password. The password has no capital letters and no `0`, `o`, `1`, `l` or `i`, so letters can't be mixed up with numbers.

## How it works

1. `setup.js` shuffles the names and has each person give to the next person in the shuffled circle, so nobody can get themselves.
2. Each person gets a random 12-character password.
3. Each person's assignee is encrypted with their own password (PBKDF2-SHA256, 600,000 iterations, then AES-256-GCM) and stored in `assignments.json` under their name.
4. The website decrypts the entry in the browser. A wrong password fails to decrypt, so only the right password reveals the name.

## Tests

```sh
node --test
```

These check that nobody is assigned to themselves, that everyone receives exactly one present, and that a wrong password can't decrypt a result.

## Known limitations

- **The organiser could peek.** The organiser hands out the passwords, so they could log in as someone. The setup never *shows* the pairings, but it relies on the organiser not snooping.
- **The participant list is public.** Anyone who opens `assignments.json` can see who is taking part (but not who got whom).
- **No limit on login attempts.** A static site can't block repeated guessing. The 12-character random passwords make guessing impractical.
- **The draw is always one big circle.** You never get small loops like Anna ↔ Erik.
- **No exclusions.** You can't say "partners must not get each other". Rerun the draw if you want a different result (and resend passwords).
